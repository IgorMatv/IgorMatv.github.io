# Дизайн: сторінка `/demos/` — запуск демо-проєктів

Дата: 2026-10-30
Джерело вимог: [`docs/launcher-hub-spec.md`](../../launcher-hub-spec.md) (далі — «ТЗ»). Цей документ
**не повторює** контракт API, таблицю станів, правила polling і обробку помилок — вони в ТЗ і
обов'язкові як є. Тут — рішення про те, де і як це живе в портфоліо.

## 1. Навіщо

Демо-проєкти (зараз тільки BeatGame) живуть на EC2, які самі засинають після 30 хв без
відвідувачів, щоб не платити за простій. Сайтом зараз майже ніхто не користується — саме тому
інстанс має спати. Портфоліо стає «пультом»: показує стан, дає запустити, чекає ~1 хв і веде в
застосунок. Друга роль — точка входу для людей, які відкрили сплячий `beatgame.app` і були
автоматично перенаправлені на портфоліо з `?wake=`.

Далі з'являться інші проєкти, тому це **окрема сторінка**, а не вставка в карточку на головній.

## 2. Цілі / не-цілі / анти-цілі

**Цілі**
- Сторінка `/demos/`, з якої можна запустити будь-який проєкт, що повертає `GET /projects`.
- Сценарій `?wake=` повертає людину в гру без жодного кліку (якщо все добре).
- Сам механізм scale-to-zero показаний як частина портфоліо.
- Додати новий проєкт = запис у бекенді + статичний контент карточки в репо портфоліо.

**Не-цілі** (як у ТЗ §7): зупинка зі сторінки, авторизація, WebSocket/SSE.
Зміна редіректу в бекенді Beat-game — **не зараз** (див. §4).

**Анти-цілі** (провал, навіть якщо «працює»)
- Сторінка тримає інстанс живим зайвим polling (ТЗ §4.5) — зводить нанівець увесь сенс.
- Open redirect через `next` (ТЗ §4.3.4).
- Нескінченна петля редіректів між портфоліо і `beatgame.app` (ТЗ §4.3.5).
- Запити до API з будь-якої сторінки, крім `/demos/` (і крім миттєвого перекидання з `/`, яке API не викликає).
- Сторінка візуально випадає з сайту.

## 3. Обмеження

- Astro 7, статичний білд, GitHub Pages, `https://igormatv.github.io`. Без UI-фреймворків:
  клієнтський код — звичайний TypeScript у `<script>` Astro-компонентів (як `ThemeToggle`,
  `MobileNavigation`).
- CI: `format:check` (Prettier), `astro check`, `build` — мають проходити.
- CORS API дозволяє тільки `https://igormatv.github.io` — локально справжнє API не працює.
- Увесь текст сайту англійською. Підписи з ТЗ (українською) перекладаються.
- Стиль — тільки існуючі токени `src/styles/tokens.css` і патерни `global.css`
  (`featured-card`, `btn--deep` / `btn--primary` / `btn--outline`, `status-badge`), обидві теми.

## 4. Рішення (погоджені з власником)

### 4.1 Розміщення
- Нова сторінка **`/demos/`** (`src/pages/demos.astro`).
- Пункт **Demos** у навігації (`Header.astro` та мобільне меню) між *Projects* і *Contact*,
  веде на `/demos/`.
- **Редірект з головної.** Бекенд лишається як є і шле на `https://igormatv.github.io/?wake=…&next=…`.
  Головна, якщо в URL є `wake`, одразу (inline-скрипт у `<head>`, до відмальовки) робить
  `location.replace('/demos/' + location.search)`. Валідацію і решту логіки робить `/demos/`.
  Без `wake` — головна поводиться як зараз.

### 4.2 Макет сторінки (варіант «C»)
Затверджений макет: `.superpowers/brainstorm/466-1793368786/content/demos-layout.html` (варіант C).
- Кікер **Live Demos**, заголовок (*Run my projects*), короткий lede.
- Смуга «How it works» з 4 кроків: *Asleep* (EC2 зупинено, нічого не коштує) → *Start* (сторінка
  викликає Lambda через API Gateway) → *Boot ~1 min* (інстанс стартує, health check застосунку) →
  *Auto-sleep* (сам зупиняється після N хв без гравців). На мобільному — у стовпчик.
- Далі — карточки проєктів у стилі `featured-card`: назва, опис, стек, лінки
  (*Project details →*, *GitHub ↗*), і **смужка керування** всередині карточки.

### 4.3 Смужка керування — стани
Затверджений макет: `.../content/demos-states.html`, частина 1. Змінюється тільки смужка.

| Стан | Точка | Текст / підпис | Дія |
|---|---|---|---|
| `stopped` | сіра | *Asleep* / *Starts in ~1 min* | **Start demo** (`btn--deep`) |
| `starting` | зелена пульсуюча | *Starting the server…* / *18 s of ~60 s* + прогрес-бар | кнопка заблокована «Starting…» |
| `booting` | зелена пульсуюча | *Starting the app…* + прогрес-бар | заблокована |
| `ready` | зелена з кільцем | *Running* / *Sleeps after 30 min with no players* | **Open Beat Game ↗** (`btn--primary`) |
| `stopping` | зелена пульсуюча | *Going to sleep…* / *It will start again automatically…* | заблокована «Waiting…» |
| помилка / таймаут 3 хв | рожева (`--color-accent-2`) | *Couldn't start* / *Please try again in a moment* | **Try again** (`btn--outline`) |
| `unavailable` / невідомий стан | рожева | *Unavailable* / *This demo is temporarily offline* | без кнопок |
| API недоступне при завантаженні | порожнє кільце | *Status unknown* / *It may still be running* | лінк *Try opening ↗* на `appUrl` |

Числа (30 хв, ~1 хв, ~60 с) беруться з API (`idleStopMinutes`, `expectedBootSeconds`), не хардкодяться.
Текст стану оголошується скрінрідерам (`aria-live="polite"` на смужці).

### 4.4 Модалка пробудження (`?wake=`)

> **Зміна після запуску в прод (2026-10-30), рішення власника.** Відхиляємось від ТЗ §4.3.2 і §4.3.5:
> - **Без авто-старту.** Модалка спершу показує *{name} is asleep* з кнопками **Start {name}** і
>   *Stay on this page*; `POST /start` іде тільки після кліку (боти й прев'ю лінків не будять EC2).
>   Після кліку — прогрес і авто-перехід на `ready`, як нижче.
> - **Проєкт уже `ready` на момент приходу** = браузер досі дістається до sleep-редиректу (Chrome
>   перевикористовує старе з'єднання з API Gateway; підтверджено в проді: «Flush socket pools» лікує).
>   Авто-переходу немає: *{name} is running*, пояснення і лінк **Open {name}**.
> - Лічильник спроб у `sessionStorage` і затримки 15 с прибрано: повернення з петлі завжди потрапляє в
>   попередній пункт, тож петля обмежена одним кліком.
> - **Оновлення:** бекенд тепер віддає `appUrl: https://play.beatgame.app` — хост, який ніколи не вказує
>   на sleep-редирект. Тому при `ready` на момент приходу портфоліо знову одразу перекидає на
>   `appUrl + next` (без кліку і без `POST /start`): петлі бути не може.
Затверджений макет: `.../content/demos-states.html`, частина 2, варіант 1 (**модалка**).
- Затемнений фон, діалог: кікер *Waking up*, заголовок *{name} is starting*, пояснення
  («The server sleeps when nobody is playing. This takes about a minute, then you'll be taken back
  automatically.»), прогрес-бар, рядок стану, кнопка **Stay on this page**.
- *Stay on this page* закриває модалку **і скасовує авто-перехід**; запуск триває у карточці,
  по `ready` — звичайна кнопка *Open*.
- Після 3 спроб (ТЗ §4.3.5) — модалка показує «Ready — open {name}» з ручним лінком.
- Помилка / таймаут — модалка показує той самий стан помилки з *Try again*.
- **API недоступне при `?wake=`** (рішення власника — варіант Б): якщо `GET /projects` не
  відповів, але `wake` збігається з `id` статичного запису в `demos.ts`, що має `appUrl`, —
  відкрити модалку в стані помилки: *Can't reach the launcher right now*, кнопки **Try again**
  (повторно `GET /projects`, і якщо вдалось — звичайний wake-сценарій) та
  **Try opening {name} ↗** (статичний `appUrl` + провалідований `next`). Жодного `POST /start` і
  жодного авто-переходу. Якщо `wake` не збігається зі статичним записом — звичайна сторінка.
- Доступність: `<dialog>` (або роль `dialog` + фокус-пастка), фокус на діалог, `Esc` = *Stay*.

### 4.5 Зміни на інших сторінках
- Карточка Beat Game на головній і кнопка у шапці `/projects/beat-game/`: «Live Product» → 
  **«Try Live Demo»**, веде на `/demos/` (не на `beatgame.app`, без `target=_blank`).
- Бейдж `statusLabel`: «Independent Product · Live» → **«Independent Product · Live Demo»**.
- Згадка в `beatGame.currentStatus` («live at beatgame.app») — лишити як є, якщо не заважає;
  рішення за виконавцем у межах «не вигадувати нового контенту».
- На цих сторінках — **жодних** запитів до API.

### 4.6 Звідки контент карточок
- Новий масив у `src/data/` (напр. `demos.ts`): по запису на `id` з API (`beatgame`) —
  опис, стек, посилання на сторінку проєкту, GitHub. Для Beat Game брати з наявного `beatGame`
  у `projects.ts`, без нового тексту.
- Список карточок, що **рендеряться**, — статичний (з `demos.ts`); що з них **керується**
  запуском — визначає відповідь `GET /projects` (ТЗ §6). Проєкт з API без статичного контенту —
  показати мінімальну карточку з `name` з API. Статичний запис без проєкту в API — карточка без
  смужки (як звичайна).
- Запис у `demos.ts` може мати необов'язковий `appUrl` (для Beat Game — `beatGame.liveUrl`). Він
  **не** вмикає керування запуском, а потрібен лише як fallback: коли `GET /projects` не відповідає,
  карточки з `appUrl` показують стан *Status unknown* з лінком *Try opening ↗* на нього.

### 4.7 Локальна розробка — мок API
- Базовий URL API — константа з env (`PUBLIC_LAUNCHER_API`), за замовчуванням продакшн-URL.
- У `astro dev` клієнт за замовчуванням працює з **мок-API в браузері** (той самий інтерфейс,
  що й реальний клієнт), який імітує `stopped → starting → booting → ready` з затримками
  і дає вибрати сценарій (початковий стан, `stopping`, `429`, `5xx`, таймаут, `unavailable`,
  API недоступне) — напр. через `?mock=<scenario>`.
- Мок **не потрапляє** в продакшн-бандл (гард `import.meta.env.DEV`).

## 5. Етапи (високий рівень; детальний план — окремо)

1. **Каркас.** Сторінка `/demos/` зі статичним контентом і смугою «How it works», пункт меню.
   Без API. Лінки/бейдж Beat Game (§4.5) ще **не** чіпати — інакше сайт втратить робочий лінк на
   гру, поки на `/demos/` немає кнопок. Можна задеплоїти — нічого не ламає.
2. **Клієнт API і стан.** Типи, клієнт, мок для dev; логіка станів/polling/помилок/таймаутів/
   `visibilitychange` як окремий модуль без DOM. Смужка керування на карточках. Наприкінці етапу —
   зміна лінків і бейджа Beat Game (§4.5).
3. **Сценарій `?wake=`.** Перекидання з головної, валідація `next`, модалка, лічильник у
   `sessionStorage`, очищення URL.
4. **Перевірка.** Чекліст приймання з ТЗ §8 на моку, потім на продакшні; мобільна верстка,
   темна тема, доступність.

## 6. Що залишено виконавцю
- Точні тексти lede і кроків «How it works» (в межах змісту вище, без вигаданих фактів).
- Внутрішня структура модулів і назви файлів.
- Як тестувати логіку станів (рекомендація: чистий модуль + `node --test`; e2e — Playwright,
  він уже є в devDependencies).
- Анімація прогрес-бару, точні відступи.

## 7. Рішення, які зробив я (не власник) — перевірити
- Пункт меню веде на окрему сторінку `/demos/`, тоді як решта пунктів — якорі головної.
- *Stay on this page* скасовує авто-перехід.
- Мок через `?mock=` і тільки в dev.
- `aria-live` + `<dialog>` для доступності.
- Fallback `appUrl` у `demos.ts` для стану «API недоступне» (§4.6).
- Зміна лінків/бейджа Beat Game переїхала з етапу 1 в кінець етапу 2 (§5).
