# ТЗ: запуск проєктів зі сторінки портфоліо (`igormatv.github.io`)

> Документ для окремої сесії в репозиторії `igormatv.github.io`. Бекенд уже
> задеплоєний і перевірений (2026-10-30); тут описано тільки контракт і
> очікувану поведінку сторінки. Код бекенду: `Beat-game/infra/terraform/launcher*.tf`,
> `infra/terraform/lambda/`.

## 1. Навіщо

Демо-проєкти (зараз BeatGame) живуть на EC2-інстансах, які **самі вимикаються
після 30 хв без відвідувачів** — щоб не платити за простій. Сторінка портфоліо
стає «пультом»: показує, чи проєкт зараз працює, дає кнопку запуску, чекає
поки він підніметься (~45–60 с) і відправляє відвідувача в застосунок.

Друга роль сторінки — **точка входу для прямих посилань**: поки BeatGame спить,
`https://beatgame.app/...` автоматично редіректить сюди з `?wake=beatgame`.

## 2. API

**Base URL:** `https://iy9imezsie.execute-api.us-east-1.amazonaws.com`

- Без авторизації. CORS дозволено тільки для `https://igormatv.github.io`
  (для локальної розробки — див. §8).
- Throttling: ~5 запитів/с, burst 10 на весь API. Перевищення → `429`.
- Відповіді — JSON, `cache-control: no-store`.

### 2.1 `GET /projects`

Всі проєкти зі станом — одним запитом. Використовувати при завантаженні сторінки.

```json
{
  "projects": [
    {
      "id": "beatgame",
      "name": "BeatGame",
      "appUrl": "https://beatgame.app",
      "state": "stopped",
      "startedAt": null,
      "expectedBootSeconds": 60,
      "idleStopMinutes": 30
    }
  ]
}
```

### 2.2 `GET /projects/{id}/status`

Один проєкт, той самий об'єкт, що в списку. Використовувати для polling.
Невідомий `id` → `404 {"error": "unknown_project"}`.

### 2.3 `POST /projects/{id}/start`

Без тіла. Ідемпотентний — повторні виклики безпечні.

| Стан до виклику | Що робить | Відповідь |
|---|---|---|
| `stopped` | запускає інстанс | `202`, `state: "starting"` |
| `starting` / `booting` / `ready` | нічого | `200` або `202`, поточний стан |
| `stopping` | нічого (AWS не дозволяє стартувати, поки інстанс зупиняється) | `200`, `state: "stopping"` — див. §4.4 |

### 2.4 Поля

| Поле | Тип | Опис |
|---|---|---|
| `id` | string | ключ проєкту, використовується в URL і в `?wake=` |
| `name` | string | відображувана назва |
| `appUrl` | string | куди відправляти користувача, коли `ready` (без слеша в кінці) |
| `state` | enum | див. §3 |
| `startedAt` | ISO-8601 \| null | час старту EC2 для `starting`/`booting`/`ready`, інакше `null`. **У відповіді на `POST /start` зазвичай `null`** (EC2 ще не оновив час) — брати з наступного `status` |
| `expectedBootSeconds` | number | типовий час `stopped → ready`, для прогрес-бару (заміряно ~44–51 с) |
| `idleStopMinutes` | number | через скільки хвилин без відвідувачів проєкт засне |

## 3. Стани

| `state` | Що відбувається | Що показати | Дія |
|---|---|---|---|
| `stopped` | спить | «Спить — запуск займе ~1 хв» | кнопка **«Запустити»** |
| `starting` | EC2 вмикається | прогрес, «Вмикаю сервер…» | чекати |
| `booting` | сервер працює, застосунок стартує | прогрес, «Запускаю застосунок…» | чекати |
| `ready` | можна користуватись | «Працює» | кнопка/лінк **«Відкрити»** → `appUrl` |
| `stopping` | саме засинає | «Засинає…» | чекати, потім автоматично стартувати (§4.4) |
| `unavailable` | щось не так (інстанс видалено/зламано) | «Недоступний» | без кнопок |

Будь-яке невідоме значення `state` трактувати як `unavailable`.

Прогрес: `elapsed = now - startedAt` (поки `startedAt == null` — від моменту
натискання кнопки), відсоток `min(95, elapsed / expectedBootSeconds * 100)`.
100% — тільки коли прийшов `ready`.

## 4. Поведінка

### 4.1 Завантаження сторінки

1. Один `GET /projects`.
2. Намалювати карточки. Контент карточки (опис, стек, скріншоти, GitHub) —
   статичний, з репозиторію портфоліо; з API беруться лише `name`/`appUrl`/стан.
   Зв'язок по `id`.
3. Якщо API недоступний (мережа/5xx) — карточки все одно показати, стан
   «невідомо», лінк на `appUrl` залишити (може, проєкт і так працює).
4. Для проєктів у `ready` — **не** опитувати далі.

### 4.2 Кнопка «Запустити»

1. `POST /projects/{id}/start`, кнопку заблокувати.
2. Polling `GET /projects/{id}/status` кожні **4 с**.
3. На `ready` — зупинити polling, показати «Відкрити».
   (Автоматично переходити тільки в сценарії §4.3.)

### 4.3 Пряме посилання: `?wake=<id>[&next=<path>]`

Сюди потрапляє людина, яка відкрила `beatgame.app`, поки той спав.
Приклад: `https://igormatv.github.io/?wake=beatgame&next=%2F%3Froom%3DWRY3H2`.

1. Якщо `wake` не відповідає жодному `id` з `/projects` — ігнорувати, звичайна сторінка.
2. Інакше — одразу `POST /start` (без кліку), показати помітний банер/модалку:
   «BeatGame прокидається, це займе близько хвилини…» + прогрес.
3. На `ready` — `location.replace(appUrl + next)`.
4. **Валідація `next` (обов'язково, захист від open redirect):** приймати
   тільки рядок, що починається з `/` і **не** з `//` і не містить `\`.
   Інакше — використовувати `/`. Склеювати лише з `appUrl` проєкту з API.
5. **Захист від петлі.** DNS після пробудження кешується до 60 с, тож перший
   перехід може знову приземлитись сюди з `?wake=`. Лічильник спроб у
   `sessionStorage` (ключ на `id`): якщо сторінка відкрилась з `?wake=`, а
   статус уже `ready` і це повторна спроба — почекати **15 с** перед
   переходом. Після **3** спроб — не редіректити, показати
   «Готово — відкрити BeatGame» з ручним лінком. Лічильник скидати після
   успішного переходу через ручний лінк або через 10 хв.
6. Прибрати `wake`/`next` з адресного рядка (`history.replaceState`), щоб
   оновлення сторінки не стартувало проєкт повторно.

### 4.4 `stopping`

Якщо після `start` прийшов `stopping` — продовжувати polling; щойно стане
`stopped`, автоматично ще раз `POST /start` (один раз). Зазвичай `stopping`
триває ~15 с.

### 4.5 Ліміти polling — важливо для економії

Коли інстанс уже працює, кожен `status` змушує бекенд звернутися до
`beatgame.app/actuator/health` — і це **рахується як активність**, що не дає
інстансу заснути. Тому:

- Опитувати **тільки** після натискання «Запустити» або в сценарії `?wake=`.
- Зупиняти polling на `ready`, `unavailable` і при помилці.
- Таймаут: якщо через **3 хв** від старту немає `ready` — зупинити polling,
  показати «Не вдалося запустити, спробуйте пізніше» + кнопка «Повторити».
- Пауза polling, коли вкладка прихована (`visibilitychange`), відновлення при поверненні.
- Ніякого фонового «оновлення статусу кожні N секунд» на звичайній сторінці.

### 4.6 Помилки

| Що | Поведінка |
|---|---|
| `429` | пропустити тик, наступний запит через 8 с |
| мережа / `5xx` | до 3 повторів поспіль з паузою 4 с, потім стан помилки + «Повторити» |
| `404 unknown_project` | карточку показати без керування запуском |

## 5. UX-підказки

- Біля проєкту, що працює: «Засне після {idleStopMinutes} хв без гравців».
- Біля сплячого: «Запуск ~{round(expectedBootSeconds/60)} хв» — щоб людина не
  злякалась очікування.
- Для BeatGame в описі варто згадати сам механізм (scale-to-zero на EC2 +
  Lambda) — це теж частина портфоліо.
- Не блокувати решту сторінки під час очікування (крім модалки в §4.3).

## 6. Додавання нового проєкту

1. Бекенд: новий запис у `local.launcher_projects` (`infra/terraform/launcher.tf`
   в репо Beat-game) → `terraform apply`. Проєкт з'явиться в `GET /projects`.
2. Портфоліо: статичний контент карточки з тим самим `id`. Проєкти без запису
   в API (статичні сайти тощо) — показувати як звичайні карточки без статусу.

Сторінка не повинна хардкодити список проєктів для керування запуском —
тільки контент. Що можна запускати, визначає `GET /projects`.

## 7. Поза скоупом

- Зупинка проєкту зі сторінки (свідомо немає — інстанс засинає сам).
- Авторизація / паролі.
- WebSocket/SSE замість polling.

## 8. Розробка і перевірка

**Локально.** CORS не пустить `localhost`. Варіанти: мок API (рекомендовано —
JSON-фікстури для всіх станів + штучна затримка переходів
`stopped → starting → booting → ready`), або тимчасово попросити додати
`http://localhost:<port>` у `launcher_allowed_origins` (Terraform, репо Beat-game).

**Перевірка контракту з терміналу** (CORS не діє на curl):

```bash
API=https://iy9imezsie.execute-api.us-east-1.amazonaws.com
curl -s $API/projects
curl -s $API/projects/beatgame/status
curl -s -X POST $API/projects/beatgame/start    # безпечно: якщо працює — no-op
```

**Чекліст приймання:**

- [ ] `ready`: карточка «Працює», лінк веде на `appUrl`, polling не йде.
- [ ] `stopped`: кнопка «Запустити» → прогрес → `ready` за ~1 хв → «Відкрити».
- [ ] `https://beatgame.app/?room=XXXXXX`, поки спить → портфоліо з банером →
      автоматично повертає на `https://beatgame.app/?room=XXXXXX`.
- [ ] `?wake=beatgame&next=//evil.com` і `next=https://evil.com` → перехід на `appUrl + "/"`.
- [ ] `?wake=unknown` → звичайна сторінка, без запитів на start.
- [ ] Оновлення сторінки після `?wake=` не стартує проєкт вдруге (URL очищено).
- [ ] Прихована вкладка не опитує API.
- [ ] Через 3 хв без `ready` — повідомлення про помилку, polling зупинено.
- [ ] Мобільна верстка.

Щоб приспати BeatGame для тесту — попросити в сесії Beat-game (там є доступ
до AWS) або почекати 30 хв без відвідувачів (автозупинка запрацює після
наступного деплою Beat-game в `production`).
